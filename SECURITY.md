# Security Policy

SeaCommons operates in a domain where security failures may expose sensitive operational information or put people at risk. Please report vulnerabilities responsibly and do not publish exploit details, credentials, private communications or real distress-case data in a public issue.

## Supported versions

SeaCommons is currently an active pilot and research project. Security fixes are applied to the latest version of the `main` branch. No long-term support versions are currently maintained.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature for this repository when available. If private reporting is unavailable, contact the maintainers through the project page without including sensitive technical details in the initial message:

https://www.suezcanal.xyz/tools/seacommons/

Include, where possible:

- the affected component and version or commit;
- a clear description of the vulnerability;
- reproduction steps using synthetic data;
- potential impact;
- suggested mitigation;
- whether you believe active exploitation is occurring.

Do not test vulnerabilities against operational deployments, real rescue cases or systems you do not own or have explicit permission to assess.

## Sensitive information

Never submit publicly:

- real distress-case coordinates, identities or communications;
- authentication tokens, API keys or credentials;
- private vessel, partner or witness information;
- operational procedures that could obstruct rescue activities;
- unredacted logs, database exports or screenshots.

## Deployment responsibilities

Operators are responsible for configuring authentication, network restrictions, encryption, backups, logging, data minimisation and retention. Public demo mode must use fictional or anonymised data only.

SeaCommons is not a certified navigation system, maritime authority service or substitute for official emergency procedures.

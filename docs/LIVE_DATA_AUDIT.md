## The main ticker (`/api/v1/live/signals`) is far more restrictive than the MDA map layer

Checked live, right now: of the 598 events currently in memory, **517 are `sanctions` domain and 77 are `grey_zone`** (99% of total volume) — and `core/intel/public_policy.is_public_domain()` returns `False` for both by pre-existing design (`core/live/projection.py`'s own comment: *"A sanctions / grey-zone signal never surfaces on the default (sar, piracy) posture"*). Only 3 `sar` + 1 `safety` domain event exist in the current window, and only 1 of those survives every other gate. This is **not a bug introduced today** — it's the general public ticker's standing conservative default, separate from the `/api/v1/live/mda-anomalies` endpoint built earlier this session specifically to carry this content to the map layer instead.

Practical effect: the sidebar list on `live.seacommons.org` will show almost no spoofing/sanctions/dark-fleet cards even when the map has hundreds of markers — those two views are fed by deliberately different eligibility rules, not the same data with different formatting. Worth deciding explicitly whether the ticker should also surface a capped, clearly-labeled sample of Security & Compliance items (consistent with today's humanitarian/security split), or whether keeping it humanitarian-only-by-default is the intended posture.

## What "reliability" actually means differently per row

Two very different failure modes are hiding under one word:
- **Rows 4, 8** (twikit, Mastodon): the *channel* can silently die (account renamed/suspended) while the *pipeline* keeps reporting "active" — because "active" today only means "the poll loop ran without throwing," not "the accounts we're tracking still exist."
- **Rows 2, 3** (spoofing, sanctions-position): the *detection logic* has no external ground truth to check itself against — a circular-track flag is our own geometric judgment call, not a second source confirming it.

## Cross-cutting management suggestions

1. **Per-handle health, not per-channel.** `/api/v1/live/sources` reports one aggregate status for all 13 twikit accounts. Split it — 5 dead handles are invisible today because 8 working ones carry the average.
2. **Prune or fix the 5 dead twikit handles** (emergencyita, UNHCR_Italia, SeaEye4, IOM_Italy, sosmediterranee) — either find their current account names or drop them; a dead handle in the config implies coverage that isn't there.
3. **Mastodon is dead weight in the registry** — either connect real accounts or remove it so `/live/sources` stops listing a channel that produces nothing.
4. **Bluesky is the one clear next win** — accounts are pre-verified alive (done this session), code isn't written yet. Highest ratio of confidence-to-effort of anything in this table.
5. **No false-positive feedback loop for MDA detections** (#2) — an operator has no way to mark "this spoofing flag was wrong," so the detector's real-world precision is never actually measured.
6. **Jamming layer (#15) wasn't re-verified this session** — worth a dedicated freshness/coverage check before leaning on it further for corroboration.

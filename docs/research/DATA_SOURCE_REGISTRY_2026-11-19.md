# DATA_SOURCE_REGISTRY — 2026-11-19

Scope: maritime intelligence, safety, environmental, satellite and humanitarian sources relevant to SeaCommons. Research was performed against primary documentation and bounded endpoint probes on 2026-11-19 UTC. A successful landing page is not treated as API access, licensing clearance, or integration.

## Status and scoring rules

Statuses are cumulative only when the earlier gates are satisfied: `DISCOVERED`, `DOCUMENTED`, `ACCESS_VERIFIED`, `SAMPLE_VALIDATED`, `LICENSE_CLEARED`, `INTEGRATION_READY`, `INTEGRATED`, `MONITORED`, `REJECTED`. Where a licence or production-use condition remains unclear, the status stops before `LICENSE_CLEARED` even if a sample request succeeded.

Priority is P0 (repair or immediate safety/evidence value), P1 (high-value pilot), P2 (useful research backlog), or P3 (reference/manual only). “Latency” means source-to-availability latency where the provider states it; otherwise it is explicitly unmeasured. Probe timings are network response times, not ingestion latency or an uptime SLA.

## Ten strongest additions or repairs

1. **IOM Missing Migrants acquisition repair (DS-05)** — the production collector is currently offline on a removed endpoint and duplicated in two hourly paths. High public-interest value, but integration must remain retrospective, coarsened and source-quality aware.
2. **MeteoAlarm OGC EDR/MQTT (DS-14)** — standards-based near-real-time official warnings with CAP lineage.
3. **EMODnet Vessel Density (DS-22)** — defensible expected-coverage baseline without acquiring restricted raw AIS.
4. **EMODnet Bathymetry (DS-21)** — open, versioned geospatial constraint for route/gap and drift QA.
5. **UNSC direct XML (DS-32)** — primary legal record to verify secondary sanctions aggregators.
6. **Algeria WIS2 OGC API (DS-15)** — rare official North African machine-readable observations and metadata.
7. **Puertos del Estado THREDDS (DS-26)** — measured waves/currents/HF-radar products for western Mediterranean validation.
8. **Paris MoU API (DS-02)** — daily official inspection/deficiency history linked by IMO, subject to account and redistribution clearance.
9. **SHOM WFS (DS-13)** — authoritative hydrographic/reference layers with standards-based access.
10. **WMO WWMIWS METAREA III (DS-10)** — official marine warnings/forecasts, provided an authorized machine feed or stable publication contract is obtained.

## Recommended initial integration set

1. **MeteoAlarm**: build a CAP-preserving fixed-origin adapter and store warning identifiers, issuer, sent/effective/expires timestamps, polygons and source links. First gate: licence/attribution clearance.
2. **EMODnet Bathymetry + Vessel Density**: add versioned offline reference snapshots, not runtime per-request WMS calls. Keep raster provenance and do not infer raw vessel tracks from density.
3. **UNSC XML**: daily conditional fetch with immutable hash, legal-basis fields and exact-identifier matching. It corroborates an official designation; it does not independently prove current beneficial ownership.
4. **Algeria WIS2**: pilot station metadata plus public WIS2 observations for RF-propagation/environmental context; never represent coastal weather stations as maritime receivers.
5. **IOM Missing Migrants repair**: only after IOM exposes a functioning, documented query/download path and reuse terms. Until then, keep the source explicitly offline rather than scraping the map.

## Rejected shortcuts

- Do not scrape Equasis, commercial vessel maps, or SafeSeaNet/CleanSeaNet.
- Do not count STAC mirrors of the same satellite item as independent evidence.
- Do not count ReliefWeb, NAVTEX republishers, or news syndication as independent of their named origin.
- Do not publish precise vulnerable-person locations or live rescue communications from humanitarian data.
- Do not treat an endpoint HTTP 200, an SDR HTTP response, or a provider READY deployment as proof of current useful data.
